# تقييم النظام — agent k2 (FastAPI)

**تاريخ:** 2026-09-17 · **نطاق المراجعة:** كوميت `2a53455` (smart receptionist upgrade)
**الطريقة:** تتبّع تنفيذ فعلي للسلسلة كاملة offline + قراءة الكود + قياس التكلفة. كل ادعاء تحته دليل.

---

## الملخص التنفيذي

| # | الحالة | الحكم |
|---|---|---|
| 1 | الحوار الطبيعي (رد الموديل يوصّل للمريض) | ✅ **شغّال فعلاً** — تم إثباته بالتتبّع |
| 2 | تغطية الوظائف (حجز/تعديل/إلغاء/مواعيد/FAQ) | ✅ موجودة — 43 response code |
| 3 | طبقة منع الاختلاق (grounding) | ❌ **متوقفة تماماً — كود ميت في الإنتاج** |
| 4 | ربط نتائج الأدوات بمصادر التحقق | ❌ ناقص |
| 5 | التكلفة لكل تيرن | ⚠️ تصل إلى **6 نداءات LLM** + FAQ مرتين |

**الخلاصة:** الأساس سليم والهدف اللي طالبه **قريب** — الموديل فعلاً بيرد بحرية وبطبيعة من بيانات Supabase.
لكن الطبقة اللي بتضمن "مش بيقول أي حاجة مش موجودة" **مش شغالة خالص**، وده أخطر فرق بين الوضع الحالي واللي عايزه.

## 1. اللي شغّال فعلاً (بالدليل)

### 1.1 رد الموديل الطبيعي بيوصل للمريض ✅

شغّلت السلسلة نفسها اللي `app/api/v1/message.py` بينفذها، برد عربي طبيعي من الموديل:

```
الموديل كتب : أهلاً بيك في عيادة النور 🌸 عندنا د. أحمد في الباطنة ود. سارة في الأطفال، تحب أحجزلك مع مين؟

المسار:
[L30] adapted          → لا يحتوي 'reply'
[L31] agent_phase      = 'understand'   ← المسار "result" ميت (متوقع)
[L33] normalize_agent_output → يحمل 'agent_reply' ✅
[L41] decision.response_code = 'CONVERSATION_ONLY'
[L60] policy.agent_reply → يمرّر النص كما هو ✅

المريض استلم : أهلاً بيك في عيادة النور 🌸 عندنا د. أحمد ... ✅ مطابق
```

**الاستنتاج:** حتى مع موت مسار `single_agent_result_phase`، الرد الطبيعي بيسلك طريقه عبر
`normalize_agent_output → orchestrator → response_policy → extract_single_agent_reply`.
يعني المشكلة **ليست** أن الردود قوالب جافة — دي كانت فرضيتي الأولى وطلعت غلط.

### 1.2 تيرن المواعيد المتاحة كذلك ✅

```
الموديل كتب : لقيتلك مع د. أحمد يوم 2026-09-20 3 مواعيد: 10:00 ص، 11:30 ص، و05:00 م. تحب أحجزلك أنهي واحد؟ 🌸
المريض استلم : نفس النص بالحرف ✅
```

### 1.3 التغطية الوظيفية موجودة ✅

43 response code في `response_policy.py` تشمل فعلاً:
`APPOINTMENT_CREATED`, `CANCEL_APPROVED`, `CANCEL_COMPLETED`, `RESCHEDULE_APPROVED`,
`RESCHEDULE_COMPLETED`, `AVAILABILITY_RESULTS`, `NO_AVAILABLE_SLOTS`, `FULLY_BOOKED`,
`SLOT_UNAVAILABLE`, `MISSING_REQUIRED_FIELDS`, `HANDOFF_REQUIRED`, `PROVIDER_UNAVAILABLE` …

و4 أدوات موصّلة بـ Supabase: `Check_Doctor_Availability`، `Search_Clinic_FAQ`،
`Get_Clinic_Services_And_Doctors`، `Get_My_Appointments`.

## 2. المشاكل — مرتبة بالخطورة

### 🔴 P0-1 — طبقة منع الاختلاق متعطّلة تماماً (كود ميت في الإنتاج)

**الدليل من الكود:**

`app/pipeline/stages_post.py:1269`
```python
"render_used": bool(_js_truthy(reply)),
```
`render_used` هنا معناه "طلع عندنا رد مش فاضي" — **مش** "الرد اتولّد من قالب ثابت".

`app/core/grounding.py:149`
```python
if (extracted or {}).get("render_used") is True:
    report["skipped"] = "template_render"
    return reply_text, report          # ← بيخرج من غير ما يفحص
```

بما إن `render_used` بيبقى `True` في **أي تيرن فيه رد**، فالـ grounding بيخرج فوراً في كل تيرن.

**الدليل التجريبي** — رد مُختلق بالكامل (دكتور وهمي + تاريخ وهمي + وقت وهمي):

| الحالة | checked | violations | النتيجة للمريض |
|---|---|---|---|
| `render_used=True` (الوضع الفعلي في الإنتاج) | False | 0 | ❌ **الرد المُختلق وصل زي ما هو** |
| `render_used=False` | True | 4 | ✅ اتمسك واتبدّل برد آمن |

```
الرد المُختلق : الموعد المتاح مع د. خالد يوم 2027-03-15 الساعة 04:30، تحب أحجزهولك؟
في الإنتاج   : المريض بيستلم الرد ده بالحرف ← لا يوجد أي حماية
```

**ليه الاختبارات مش كاشفة؟** `tests/test_grounding.py` كله unit tests بتنادي `ground_reply`
مباشرة وبتحدد `render_used` بإيدها. **مفيش اختبار واحد بيمرّ بالـ runner.** فالاختبارات بتعدّي
والـ feature ميتة في الإنتاج — وده نمط كلاسيكي في الأنظمة المترجمة من n8n.

**الأثر على هدفك:** أنت قلت "مش بيقول أي شئ مش موجود" — حالياً **مفيش أي شيء بيمنع ده**.

### 🔴 P0-2 — نتائج الأدوات مش داخلة في مصادر التحقق

`app/api/v1/message.py:471-484` — الـ `sources` اللي بيتبني منها الـ whitelist:

```python
sources={"normalized": ..., "state": ..., "clinic": ..., "policy": ...,
         "decision": ..., "repaired": ..., "faq": ...}
```

**مفيش `availability` ولا `patient_appointments` ولا `services_doctors`.**

`docs/agent_upgrade_design.md` نفسها بتعترف: *"v1.1 (planned): thread availability-tool
results into the whitelist."*

**الخطورة الحقيقية:** لو صلّحنا P0-1 لوحده **هنكسر النظام** — لأن الموديل لما يعرض مواعيد
حقيقية جابها من الأداة، الأوقات دي مش في الـ whitelist → هتتعتبر "اختلاق" → الرد كله هيتشال
ويتبدّل بـ `عذرًا، حصل لبس من عندي` — يعني بالظبط الوظيفة اللي أنت عايزها هتتعطل.

**لازم الإصلاحين يتنفذوا مع بعض، مش واحد ورا التاني.**

### 🟠 P1-1 — التكلفة: لحد 6 نداءات LLM في التيرن الواحد

```
tool-loop     : max_turns = 5      (dialogue.py:285)
repair chain  : +1                 (message.py:308)
──────────────────────────────────
الإجمالي      : حتى 6 نداءات لكل رسالة مريض

حجم الـ system prompt : 2,798 حرف ← بيتبعت 5 مرات = 13,990 حرف
حجم مخطط الأدوات      : 2,249 حرف ← بيتبعت 4 مرات =  8,996 حرف
```

مفيش **prompt caching**، ومفيش **short-circuit للتيرنات الرخيصة** (زي "أيوه"/"لا" في مرحلة
التأكيد، أو اختيار رقم من المواعيد المعروضة) — `docs/agent_upgrade_design.md` بند P2.1/P2.3
لسه متعملش. دي أكبر نقطة توفير متاحة.

### 🟠 P1-2 — FAQ بتتجاب مرتين في نفس التيرن

- `message.py:242` — prefetch على **كل** تيرن (SQL + tokens)
- `dialogue.py:336-344` — `Search_Clinic_FAQ` كأداة جوّه الـ loop

يعني الـ SQL + التوكنز بيتدفعوا مرتين. البند P1.2 في التصميم كان هدفه إزالة الـ prefetch
المشروط، لكن الكود الحالي بيعمل prefetch **غير مشروط** + الأداة مع بعض.

### 🟡 P1-3 — كود ميت

`dialogue.py:245 call_primary_model()` (النسخة القديمة بدون أدوات) — **صفر استخدام** في

### 🟡 P2 — "مخّين" ممكن يختلفوا

في تتبّع المواعيد، الموديل بيسأل المريض سؤال طبيعي ("تحب أحجزلك أنهي واحد؟") بينما الـ
orchestrator طلع `MISSING_REQUIRED_FIELDS`.

الرد للمريض طلع صح (الموديل كسب)، **لكن الحالة الداخلية** (`state_patches` /
`conversation_stage`) اتسجلت على أساس إن في حقول ناقصة. ده بيخلي التيرن اللي بعده ممكن
يسأل عن حاجة الموديل ما طلبهاش. **محتاج تحقق على بيانات حقيقية قبل ما نحكم.**

### المرحلة ج — تقليل التكلفة (P1-1)

| # | العمل | التوفير المتوقع |
|---|---|---|

| C4 | عدم إرسال مخطط الأدوات في تيرن الـ JSON النهائي | ~2,249 حرف/تيرن |
